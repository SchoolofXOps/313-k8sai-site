Lab — Estimate VRAM, Capacity and Cost for an AI Service

Lab Truth Contract — SIMULATED

Every figure is arithmetic from stated assumptions — an estimate, not a measurement; no cluster, no device.

In this lab you will size an AI service on paper, using small scripts that do the arithmetic and print their assumptions first. You will work out how much memory a model needs, how many accelerators a given demand needs, and what a 64-accelerator fleet costs at low and at high utilisation. You finish with two documents in your own repository, a capacity model and a cost model.

Run every command from the root of your clone of the labs repository, the same clone you used in Module 1. No cluster is needed, and nothing here touches kubectl, kind or docker. If you arrived without your own remote, do the Module 1 step that points your clone at a repository you own first.

Where the platform stands​

After Module 1 you have a platform record that holds grid-platform/docs/baseline-failures.md and the grid-core cluster profile under grid-platform/clusters/grid-core/, and a cluster that you tore down. The platform can do exactly what it could then. It still cannot place a Pod that asks for a device, and it still cannot tell you whether a model server fits on the machine you gave it.

This lab adds numbers, not features. When you finish, your repository holds grid-platform/docs/capacity-model.md and grid-platform/docs/cost-model.md. The first says how many accelerators one service needs and how sure you are. The second says what an idle fleet costs and what each of four changes would save. Every later module that sizes something will point back to these two files.

All prices and lever effects are inputs you can change. The prices in the files are round numbers for the arithmetic, and each is marked "replace with your own quote". They are not market rates. The model figures come from published model cards, with the revision named in each input file.

Part 2: capacity from demand​

Now comes the question a team would bring to you: we expect this much traffic, so how many accelerators do we ask for? Read the demand file first. Every value in it is a declared assumption.

cat m2/inputs/demand.conf

[ Expected output ]

# Demand for one model service. Every value is a declared assumption: replace with your own numbers.
model_file=m2/inputs/models/qwen2.5-7b-instruct.conf
accelerators_file=m2/inputs/accelerators.conf
accelerator=l40s
precision_bytes=2
overhead_fraction=0.10
# Peak requests per second reaching the service.
arrival_rate_rps=20
# Average time one request stays in the system, in seconds. Replace with your own observed figure.
mean_latency_s=8
# Tokens held in the cache per request.
context_tokens=4096
# Average output tokens per request.
tokens_per_request=400
# Output tokens per second one replica sustains. Replace with your own load-test result.
tokens_per_second_per_replica=3000
# Extra replicas kept so the loss of capacity does not break the service, as a fraction.
failure_reserve_fraction=0.20
# Accelerators lost to placement gaps, as a fraction.
fragmentation_fraction=0.10

Two of those values are marked "replace with your own". The latency must come from what you observe on your own service, and the tokens per second for one replica from your own load test. This course does not supply them. Run the calculator.

Read the result in order. Concurrent requests come from arrival rate into latency. Replicas from memory and replicas from throughput are two separate answers, and the larger one binds, that is, it is the one you must plan for. Then the failure reserve and the fragmentation allowance are added, and you get the recommended number of accelerators. Observe which of the two binds, and which inputs in the sensitivity table move the answer at all.

Part 3: the cost model for a 64-accelerator fleet​

Cost comes after capacity because capacity decides how many accelerators you pay for. The five percent utilisation on the low row comes from Cast AI's 2026 State of Kubernetes Optimization report, which is a cited vendor figure and not a figure this course produced. Read the inputs. Prices and lever effects are declared assumptions, and the file says so.

cat m2/inputs/cost.conf

[ Expected output ]

# Cost inputs for a fleet. Every value is a declared assumption.
# Prices: declared assumptions - replace with your own quote. Not market rates.
price_on_demand_usd_per_accel_hour=4.00
price_reserved_usd_per_accel_hour=2.50
price_spot_usd_per_accel_hour=1.50
# Which price the annual cost uses: on_demand, reserved or spot.

# The two utilisation levels to compare, as fractions of hours doing useful work.
utilisation_low=0.05
utilisation_high=0.60
# Output tokens per second one busy accelerator produces. Replace with your own load-test result.

# The four levers. Declared assumptions - replace with your own measurement.
# share: absolute rise in utilisation from putting several workloads on one accelerator.
share_utilisation_gain=0.10
# queue: absolute rise in utilisation from a queue that keeps accelerators fed.
queue_utilisation_gain=0.20
# pack: accelerators released because the same work is packed onto fewer.
pack_accelerators_released=8
# reclaim: fraction of idle hours returned (not paid for) by reclaiming idle allocations.
reclaim_idle_fraction=0.30

COST=$(bash m2/cost-model.sh m2/inputs/cost.conf)
{
  echo '# Cost model'

  echo '## Fleet cost at 5% and at 60% utilisation'
  echo
  echo "The 5% figure comes from Cast AI's 2026 State of Kubernetes Optimization report. It is a cited vendor figure, not a figure this course produced, and 60% is a design target used for comparison. Prices are declared assumptions: replace with your own quote."
  echo
  echo '~~~text'
  printf '%s\n' "$COST" | sed -n '/^FLEET AT/,/^$/p'
  echo '~~~'
  echo
  echo '## The four levers'
  echo
  echo 'Each lever is applied alone against the low-utilisation baseline. Their effects overlap, so do not add them up. Every effect is a declared assumption: replace with your own measurement.'
  for lever in share queue pack reclaim; do
    echo
    case "$lever" in
      share) echo '### Share' ;;
      queue) echo '### Queue' ;;
      pack) echo '### Pack' ;;
      reclaim) echo '### Reclaim' ;;
    esac
    echo
    echo '~~~text'
    printf '%s\n' "$COST" | grep "^$lever "
    echo '~~~'
  done
} > grid-platform/docs/cost-model.md

Known failures and their fixes​

No step failed in either of the course's two runs of this page. Every command exited cleanly, no step needed a cluster, and the checks passed both times. The one entry below is a wrong figure, not an error, and it is listed because a clone taken before the fix still prints it.

The reclaim line reads cost_usd=1603430 and saving_usd=639129. Seen in the course's first run, at the step that runs bash m2/cost-model.sh m2/inputs/cost.conf. Those two figures add up to 2242559, one dollar short of the fleet cost of 2242560, because that version of the calculator rounded each figure on its own. The calculator now rounds the returned idle hours once and works out the saving and the cost from that, so the line reads cost_usd=1603432 and saving_usd=639128, as shown above.

If you see the older figures, your copy of m2/cost-model.sh is older than the course's. Take the current file from the course's repository and run the step again. Nothing else in your clone changes.
